# 📄 แผ่นที่ 1: ข้อที่ 1 — Intro to NLP (1 คะแนน)
<!-- ======================================================================= -->

### 1.1 นิยามของ NLP (Definition & Foundations)
- **NLP (Natural Language Processing)** คือ จุดตัดของ 3 ศาสตร์:
  1. **ภาษาศาสตร์ (Linguistics):** กฎไวยากรณ์, สัทศาสตร์, โครงสร้างและความหมายของภาษา
  2. **วิทยาการคอมพิวเตอร์ (Computer Science):** โครงสร้างข้อมูล, อัลกอริทึม, ประสิทธิภาพเชิงคำนวณ
  3. **ปัญญาประดิษฐ์ (Artificial Intelligence):** การแทนความรู้ (Representation), การเรียนรู้ของเครื่อง (ML/DL), การอนุมานเหตุผล (Reasoning)
- **เป้าหมาย:** เพื่อให้คอมพิวเตอร์สามารถ **เข้าใจ (Understand)**, **ตีความ (Interpret)**, และ **สร้าง (Generate)** ภาษามนุษย์ได้อย่างถูกต้องเป็นธรรมชาติ

---

### 1.2 สถาปัตยกรรมหลักของระบบ NLP (3 เสาหลัก)
```text
[Raw Human Text] ──> [ NLU ] ──> [ KAI ] ──> [ NLG ] ──> [Natural Human Output]
                      (ขาเข้า)    (แกนกลาง)    (ขาออก)
```
1. **NLU (Natural Language Understanding) — ขาเข้า (Input $\to$ Meaning):**
   - ทำหน้าที่แปลงข้อความดิบให้เป็นโครงสร้างความหมาย
   - จัดการเรื่องการตัดคำ, วิเคราะห์ไวยากรณ์, สกัดเจตนา (Intent Extraction) และเอนทิตี (Slots/Entities)
2. **KAI (Knowledge Acquisition & Inferencing) — สมอง/แกนกลาง (Reasoning):**
   - จัดเก็บความรู้ในรูป Knowledge Representation / Ontology / Knowledge Graph
   - ทำการอนุมานเชิงเหตุผล (Inference & Logic Reasoning) เพื่อหาคำตอบหรือแนวทางแก้ไข
3. **NLG (Natural Language Generation) — ขาออก (Meaning $\to$ Text/Speech):**
   - นำผลลัพธ์เชิงตรรกะมาสังเคราะห์และสร้างเป็นข้อความหรือเสียงพูดภาษาธรรมชาติที่ถูกต้องตามหลักไวยากรณ์และสละสลวย

---

### 1.3 5 ระดับชั้นโครงสร้างทางภาษา (Levels of Linguistic Structure)
1. **Morphology (ระดับหน่วยคำ/สัณฐานวิทยา):** โครงสร้างของคำ รากศัพท์ คำนำหน้า/ต่อท้าย (Prefix/Suffix)
2. **Syntax (ระดับไวยากรณ์/วากยสัมพันธ์):** โครงสร้างประโยค ความสัมพันธ์ระหว่างคำตามกฎไวยากรณ์
3. **Semantics (ระดับอรรถศาสตร์):** ความหมายตรงตัวตามตัวอักษรของประโยคเดี่ยว
4. **Discourse (ระดับสัมพันธสาร):** ความหมายเชื่อมโยงระหว่างประโยค การอ้างอิงของคำสรรพนาม (Coreference Resolution)
5. **Pragmatics & World Knowledge (ระดับวัจนปฏิบัติศาสตร์):** ความหมายที่แท้จริงตามบริบท เจตนาของผู้พูด วัฒนธรรม และความรู้รอบตัวเกี่ยวกับโลกจริง

---

### 1.4 5 ความท้าทายหลักของ NLP และบริบทภาษาไทย (Core Challenges)
| ความท้าทาย | นิยาม | ตัวอย่างในภาษาไทย |
| :--- | :--- | :--- |
| **1. Abstractness** (นามธรรม) | ความหมายแฝง ประชดประชัน ไม่ตรงตัวอักษร | • *"สวยกี่โมง"* = **ไม่สวย**<br>• *"ได้อยู่"* = **ไม่ได้ / แย่**<br>• *"ไปให้แม่แกทำ"* = ปฏิเสธ/ประชด |
| **2. Combinability** (ผสมคำไม่จำกัด) | คำเดี่ยวนำมารวมกันเกิดความหมายใหม่ | • แม่ + น้ำ = **แม่น้ำ** (river)<br>• กับ + ข้าว = **กับข้าว** (side dish ไม่มีข้าวสาร) |
| **3. Evolutiveness** (ภาษาไม่หยุดนิ่ง) | วิวัฒนาการเร็ว คำสแลง คำย่อเกิดขึ้นตลอด | • *"ใช่ไหม"* $\to$ *"ใช่ปะ"* $\to$ *"ช้ะ"*<br>• *"จะรั่ว"* (ขำมากจนทนไม่ไหว), *"เลิศ"* $\to$ *"เริด"* |
| **4. Nonstandardness** (ความไร้ระเบียบ) | คำพิมพ์ผิด ภาษาพูด สลับคำขยายได้อิสระ | • *"กำลังจะไปกินข้าว"*, *"กินข้าวอยู่"*, *"ไปกินข้าวแล้ว"* |
| **5. Subjectivity** (ขึ้นกับบุคคล/บริบท) | อารมณ์ วัฒนธรรม ภูมิภาค ส่งผลต่อความหมาย | • เมนู *"แกงส้ม"* (ภาคกลาง) vs *"แกงส้ม"* (ภาคใต้ คือแกงเหลือง) |

> ⚠️ **ปัญหาเฉพาะตัวที่ร้ายแรงที่สุดของภาษาไทย:** ภาษาไทยเขียนต่อเนื่องกัน **ไม่มีช่องว่างคั่นคำ (No whitespace word boundary)** ทำให้ต้องทำ **Word Segmentation** ก่อนทำงานอื่นเสมอ!

---

### 1.5 Upstream Tasks vs Downstream Tasks
- **Upstream Tasks (งานระดับรากฐาน/เตรียมข้อมูล):** สกัดคุณลักษณะทางภาษาศาสตร์เบื้องต้น
  - *ตัวอย่าง:* Tokenization, Word Segmentation, POS Tagging, Syntactic Parsing, Lemmatization
- **Downstream Tasks (งานประยุกต์ใช้งานจริง):** นำผลลัพธ์จาก Upstream ไปประมวลผลต่อ
  - *ตัวอย่าง:* Text Classification, Sentiment Analysis, Machine Translation, Text Summarization, Question Answering (QA)
- *(หมายเหตุ: Named Entity Recognition: NER จัดเป็นงานบริดจ์ระหว่าง Upstream และ Downstream)*

---

### 1.6 เครื่องมือมาตรฐาน (NLP Libraries)
- **NLTK:** ใช้ในการเรียนการสอนและงานวิจัย มี Corpus และเครื่องมือคลาสสิกครบ
- **spaCy:** ใช้งานจริงระดับ Production (Fast, Industrial-Strength) มี Pipeline สำเร็จรูป
- **PyThaiNLP:** ไลบรารีมาตรฐานสำหรับภาษาไทยโดยเฉพาะ (ตัดคำ, กำกับชนิดคำ, วิเคราะห์เสียง)
- **Hugging Face (`transformers`):** ฮับกลางสำหรับดาวน์โหลดและ Fine-tune โมเดล Transformer / LLM ยุคใหม่

### 2.1 Tokenization คืออะไร และทำไม $1\text{ Token} \neq 1\text{ Word}$
- **Tokenization** คือ กระบวนการตัดแบ่งข้อความดิบ (Raw Text) ออกเป็นหน่วยย่อย (Tokens) ก่อนแปลงเป็นตัวเลข (IDs)
- **1 Token $\neq$ 1 Word:** คำว่า `"don't"` อาจถูกตัดได้หลายแบบขึ้นกับ Tokenizer:
  - แบบ 1 token: `["don't"]`
  - แบบ 2 tokens: `["do", "n't"]` (ตามมาตรฐาน Penn Treebank)
  - แบบ 3 tokens: `["don", "'", "t"]`

---

### 2.2 เปรียบเทียบ 3 แนวทางการตัด Token
| แนวทาง | หลักการ | ข้อดี | ข้อจำกัด |
| :--- | :--- | :--- | :--- |
| **Word-Based** | ตัดตามช่องว่างหรือวรรคตอน | เข้าใจง่าย ความหมายระดับคำชัดเจน | • เกิดปัญหา **Out-of-Vocabulary (OOV)**<br>• Vocab ขนาดใหญ่เกินไป (หลักแสน-ล้าน) |
| **Character-Based** | ตัดแยกรายตัวอักษร | • ไม่มีปัญหา OOV (เก็บครบทุกตัว)<br>• Vocab เล็กมาก (~100-300 ตัว) | • สูญเสียความหมายของคำ<br>• Sequence ยาวมาก กิน Memory มหาศาล |
| **Subword-Based**<br>*(BPE, WordPiece)* | แบ่งเป็นหน่วยคำย่อยที่พบบ่อย | **สมดุลสมบูรณ์แบบ** จัดการคำแปลกใหม่ได้ ไม่เกิด OOV ขนาด Vocab พอดี | ต้องเทรน Tokenizer บน Corpus ล่วงหน้า |

---

### 2.3 ตารางเปรียบเทียบ Subword Algorithms ยอดนิยม (ออกสอบบ่อย!)
| คุณลักษณะ | Byte-Pair Encoding (BPE) | WordPiece | Unigram Language Model (ULM) |
| :--- | :--- | :--- | :--- |
| **ทิศทาง** | Bottom-up (รวมขึ้นไป) | Bottom-up (รวมขึ้นไป) | Top-down (เริ่มจากใหญ่แล้วตัดทิ้ง) |
| **เกณฑ์การ Merge / Prune** | เลือกคู่ที่ **มีความถี่สูงสุด (Most Frequent Pair)** | เลือกคู่ที่ **เพิ่ม Language Model Likelihood สูงสุด** | ค่อยๆ **ตัดทอน (Prune)** หน่วยย่อยที่ลด Likelihood น้อยสุดออก |
| **สัญลักษณ์กำกับ** | ใช้ตัวคั่นเฉพาะ เช่น `Ġ` (GPT) | ใช้ Prefix `##` เช่น `play`, `##ing` | ใช้เครื่องหมาย ` ` (SentencePiece) |
| **โมเดลที่นำไปใช้** | **GPT-2, GPT-3, GPT-4, LLaMA, RoBERTa** | **BERT, DistilBERT, Electra** | **SentencePiece, T5, ALBERT** |

---

### 2.4 วิธีการคำนวณฝึก BPE ด้วยมือ (BPE Hand Calculation Step-by-Step)
**สมมติ Corpus:** `"new" (2 ครั้ง), "renew" (2 ครั้ง), "set" (1 ครั้ง), "reset" (1 ครั้ง)`
1. **เริ่มต้น (Init):** แตกเป็นตัวอักษรเดี่ยว
   - `n e w (2)` | `r e n e w (2)` | `s e t (1)` | `r e s e t (1)`
   - $V_0 = \{e, n, r, s, t, w\}$
2. **รอบที่ 1:** นับความถี่คู่ตัวอักษรที่ติดกัน:
   - คู่ $(n, e)$ เกิดใน new (2) + renew (2) = **4 ครั้ง** (มากที่สุด) $\implies$ รวมเป็น `"ne"`
   - Corpus กลายเป็น: `ne w (2)` | `r e ne w (2)` | `s e t (1)` | `r e s e t (1)`
   - $V_1 = \{e, n, r, s, t, w, \text{"ne"}\}$
3. **รอบที่ 2:** นับความถี่คู่ติดกันใหม่:
   - คู่ $(ne, w)$ เกิดใน ne-w (2) + renew (2) = **4 ครั้ง** $\implies$ รวมเป็น `"new"`
   - Corpus กลายเป็น: `new (2)` | `r e new (2)` | `s e t (1)` | `r e s e t (1)`
   - $V_2 = V_1 \cup \{\text{"new"}\}$
4. **รอบที่ 3:** นับคู่ติดกันใหม่:
   - คู่ $(r, e)$ เกิดใน renew (2) + reset (1) = **3 ครั้ง** $\implies$ รวมเป็น `"re"`
   - Corpus กลายเป็น: `new (2)` | `re new (2)` | `s e t (1)` | `re s e t (1)`
5. **รอบที่ 4:** รวม $(re, new) \to \text{"renew"}$, รวม $(s, e) \to \text{"se"}$, รวม $(se, t) \to \text{"set"}$
   - คำว่า `"reset"` จึงถูกแทนด้วย Subword: `["re", "set"]`

> 📌 **กฎการนำไป Encode ข้อความใหม่ (Deterministic Rules):** เมื่อนำ Tokenizer ที่เทรนเสร็จแล้วไปตัดคำใหม่ ให้ไล่ใช้กฎ Merge ตาม **ลำดับที่เรียนรู้มาตอนเทรนเท่านั้น** (ห้ามนำความถี่ในข้อความทดสอบมาตัดสิน)

---

### 2.5 Byte-Level BPE ใน LLM ยุคใหม่
- ทำงานบน **Byte UTF-8 (256 Base Bytes)** แทนที่จะเป็นตัวอักษร Unicode
- **ข้อดีเด่น:** รองรับทุกภาษาในโลก อีโมจิ อักขระพิเศษ โดย **ไม่มี Unknown Token (`<unk>`) อีกต่อไป!**
- **Language Bias (ข้อจำกัด):** ภาษาอังกฤษใช้ 1 token ต่อ 1 คำ แต่ภาษาที่ทรัพยากรน้อย (เช่น ภาษาไทย) 1 ตัวอักษรอาจใช้ 3 ไบต์ ทำให้กินจำนวน Token มากกว่าและต้นทุน API สูงกว่า

---

### 2.6 ขั้นตอนการทำ Text Normalization
1. **Lowercasing:** แปลงเป็นตัวพิมพ์เล็ก (เช่น `"Hello"` $\to$ `"hello"`)
2. **Punctuation Removal / Handling:** แยกหรือลบเครื่องหมายวรรคตอน
3. **Stop Word Removal:** กรองคำพบบ่อยที่ไม่มีความหมายเฉพาะเจาะจงออก เช่น `"is", "the", "at"`
4. **Stemming vs Lemmatization:**
   - **Stemming:** ตัดส่วนลงท้ายคำตามกฎฮิวริสติก (เช่น Porter Stemmer: `"studies"` $\to$ `"studi"`, `"running"` $\to$ `"run"`)
   - **Lemmatization:** คืนรูปคำสู่รูปพจนานุกรม (Lemma) โดยพิจารณาบริบทและ POS Tag (เช่น `"studies"` $\to$ `"study"`, `"better"` $\to$ `"good"`)
5. **Unicode Normalization (NFC / NFD):** จัดการสระ/วรรณยุกต์ซ้อนให้มีรหัสมาตรฐานเดียวกัน

# 📄 แผ่นที่ 3: ข้อที่ 3 — Word Segmentation (ส่วนที่ 1 ของ 10 คะแนน)
<!-- ======================================================================= -->

### 3.1 ความท้าทายของการตัดคำภาษาไทย
1. ไม่มีช่องว่างคั่นคำ (No whitespace delimiter)
2. ความกำกวมของขอบเขตคำ (Boundary Ambiguity) เช่น:
   - `"ตากลม"` $\to$ `"ตาก-ลม"` (นั่งตากลม) หรือ `"ตา-กลม"` (ตากลมโต)
   - `"ไปหามเหสี"` $\to$ `"ไป-หา-มเหสี"` หรือ `"ไป-หาม-เหสี"`

---

### 3.2 Maximum Matching: FMM vs BMM (ออกสอบแน่นอน!)
- **Forward Maximum Matching (FMM):** สแกนจาก **ซ้ายไปขวา**
  1. เริ่มที่ตำแหน่ง $i = 0$
  2. มองหาคำในพจนานุกรมที่มีความยาวมากที่สุด (ตั้งแต่ `max_len` ถอยลงมาถึง 1)
  3. ถ้าพบคำในดิก $\implies$ ตัดคำนั้นออก เลื่อนตำแหน่ง $i$ ไปข้างหน้า
  4. ถ้าไม่พบคำใดเลย $\implies$ ตัดตัวอักษรเดี่ยว 1 ตัว แล้วเลื่อนไป
- **Backward Maximum Matching (BMM):** สแกนจาก **ขวาไปซ้าย**
  1. เริ่มที่ตำแหน่งท้ายสุด $j = \text{len}$
  2. มองหาคำในพจนานุกรมที่ยาวที่สุดที่สิ้นสุดที่ตำแหน่ง $j$
  3. ถ้าพบคำในดิก $\implies$ ตัดคำนั้นออก เลื่อนตำแหน่ง $j$ ถอยหลัง
  4. ถ้าไม่พบคำใดเลย $\implies$ ตัดตัวอักษรเดี่ยว 1 ตัว

#### 📝 ตัวอย่าง Trace ข้อสอบ: `"อากาศตากลม"` (พจนานุกรม: `{อากาศ, ตาก, ตา, ลม, กลม}`)
- **FMM (ซ้าย $\to$ ขวา):**
  - เริ่มที่ตัวแรก: คำยาวสุดที่เจอคือ `"อากาศ"` (ตัด `"อากาศ"`)
  - ข้อความที่เหลือ: `"ตากลม"`
  - สแกนหาคำยาวสุด: เจอคำว่า `"ตาก"` (ยาว 3 ตัวอักษร ยาวกว่า `"ตา"`)
  - ข้อความที่เหลือ: `"ลม"` $\implies$ เจอคำว่า `"ลม"`
  - **ผลลัพธ์ FMM:** `["อากาศ", "ตาก", "ลม"]`
- **BMM (ขวา $\to$ ซ้าย):**
  - เริ่มจากท้าย: ดูสตริงย่อยที่ลงท้ายที่ตัวสุดท้าย (`"ตากลม"`)
  - คำยาวสุดจากขวาที่อยู่ในพจนานุกรมคือ `"กลม"` (ยาว 3 ตัวอักษร ยาวกว่า `"ลม"`)
  - ข้อความที่เหลือด้านหน้า: `"อากาศตา"`
  - คำยาวสุดจากขวาที่เจอคือ `"ตา"`
  - ข้อความที่เหลือด้านหน้า: `"อากาศ"` $\implies$ เจอคำว่า `"อากาศ"`
  - **ผลลัพธ์ BMM:** `["อากาศ", "ตา", "กลม"]`

### 3.3 Statistical Segmentation (การตัดคำด้วยสถิติและความน่าจะเป็น)
#### 1. Unigram Model
$$P(w_1, w_2, \dots, w_k) = \prod_{i=1}^k P(w_i) = \prod_{i=1}^k \frac{\text{Count}(w_i)}{N}$$
*(หรือคิดในรูปผลรวม Log: $\sum \log P(w_i)$)*

**ตัวอย่างคำนวณ (จาก Assignment 2 DIY 2):**
สมมติให้เปรียบเทียบการตัดคำว่า `"ลมกลม"` ระหว่าง 1 คำ vs 2 คำ โดยมีสถิติคลังข้อมูล $N = 100,000$:
- $\text{Count}(\text{"ลมกลม"}) = 50$ (คำประสมหายาก)
- $\text{Count}(\text{"ลม"}) = 5,000$, $\text{Count}(\text{"กลม"}) = 3,000$ (คำเดี่ยวพบบ่อย)
- $P(\text{1 word}) = P(\text{"ลมกลม"}) = \frac{50}{100,000} = 0.0005$
- $P(\text{2 words}) = P(\text{"ลม"}) \times P(\text{"กลม"}) = \frac{5,000}{100,000} \times \frac{3,000}{100,000} = 0.05 \times 0.03 = 0.0015$
- **ผลลัพธ์:** การตัดเป็น 2 คำ ชนะ! ชนะด้วยอัตราส่วน $\frac{0.0015}{0.0005} = 3$ เท่า

#### 2. Bigram Model (บริบท 1 คำก่อนหน้าช่วยแก้ความกำกวมได้มหาศาล)
$$P(w_1, \dots, w_k) = P(w_1) \prod_{i=2}^k P(w_i \mid w_{i-1}) = P(w_1) \prod_{i=2}^k \frac{\text{Count}(w_{i-1}, w_i)}{\text{Count}(w_{i-1})}$$

**ตัวอย่างจาก Lab 2:** มีคำว่า `"นั่ง"` นำหน้า `"ตากลม"`
- ทางเลือก A (`ตา-กลม`): $P(\text{ตา} \mid \text{นั่ง}) \times P(\text{กลม} \mid \text{ตา}) = \frac{4}{2,000} \times \frac{380}{4,200} = 0.002 \times 0.090476 = 1.8095 \times 10^{-4}$
- ทางเลือก B (`ตาก-ลม`): $P(\text{ตาก} \mid \text{นั่ง}) \times P(\text{ลม} \mid \text{ตาก}) = \frac{180}{2,000} \times \frac{240}{320} = 0.09 \times 0.75 = 0.0675$
- **เปรียบเทียบ:** ทางเลือก B (`นั่งตากลม`) มีความน่าจะเป็นสูงกว่าทางเลือก A ถึง $\frac{0.0675}{1.8095 \times 10^{-4}} \approx \mathbf{373\text{ เท่า!}}$

### 4.1 ความกำกวมของ POS (POS Ambiguity)

  - *"Fruit flies like a banana"* $\implies$ `flies` เป็น **NOUN** (แมลงวันผลไม้)

---

### 4.2 เปรียบเทียบ 3 แนวทาง POS Tagging
| แนวทาง | ชนิดของโมเดล | หลักการทำงาน | จุดเด่น | จุดด้อย |
| :--- | :--- | :--- | :--- | :--- |
| **Rule-based & Brill TBL** | Heuristic / Hybrid | ใช้พจนานุกรม + เรียนรู้ Transformation Rules แก้ Tag ผิด | อธิบายได้ชัดเจน ไม่ต้องใช้สถิติซับซ้อน | เขียนกฎครอบคลุมยาก ขยายสเกลลำบาก |
| **HMM (Hidden Markov Model)** | **Generative Model** | จำลอง $P(W, T)$ ด้วย Transition $P(t_i \mid t_{i-1})$ และ Emission $P(w_i \mid t_i)$ | คำนวณเร็ว ถอดรหัสด้วย Viterbi Dynamic Prog. | มีสมมติฐาน Independence เข้มงวด, ใส่ Feature ซ้อนทับไม่ได้ |
| **CRF (Linear-Chain CRF)** | **Discriminative Model** | จำลอง $P(T \mid W)$ โดยตรง ด้วย Feature Functions $f_k(t_{i-1}, t_i, W, i)$ | **ใส่ Overlapping Features ได้อิสระ** (Word Shape, Suffix), แม่นยำที่สุด | เทรนช้ากว่า ต้องการ Labeled Data มาก |

---

### 4.3 สูตรคณิตศาสตร์ของ HMM
1. **Transition Probability:** $a_{ij} = P(t_j \mid t_i)$ (ความน่าจะเป็นที่จะเปลี่ยนจาก Tag $i$ ไปยัง Tag $j$)
2. **Emission Probability:** $b_j(w) = P(w \mid t_j)$ (ความน่าจะเป็นที่ Tag $j$ จะปล่อยคำ $w$ ออกมา)
3. **เป้าหมาย:** $\hat{T} = \arg\max_T \prod_{i=1}^n P(t_i \mid t_{i-1}) \cdot P(w_i \mid t_i)$

---

### 4.4 ขั้นตอนคำนวณอัลกอริทึม Viterbi ด้วยมือ (กดเครื่องคิดเลข!)
กำหนดให้ $v_t(j)$ คือค่าความน่าจะเป็นสูงสุดของเส้นทาง Tag ที่มาสิ้นสุดที่ Tag $j$ ณ ตำแหน่งคำที่ $t$

#### 1. การเริ่มต้น (Initialization, $t = 1$):
$$v_1(j) = a_{<s>, j} \times b_j(w_1)$$
$$bt_1(j) = 0$$

#### 2. ขั้นตอนวนซ้ำ (Recursion, $t > 1$):
$$v_t(j) = \max_{i=1}^N \Big[ v_{t-1}(i) \times a_{ij} \Big] \times b_j(w_t)$$
$$bt_t(j) = \arg\max_{i=1}^N \Big[ v_{t-1}(i) \times a_{ij} \Big]$$

#### 3. ขั้นตอนสิ้นสุด (Termination, $t = T$):
$$P^* = \max_{j=1}^N v_T(j), \quad \hat{t}_T = \arg\max_{j=1}^N v_T(j)$$

#### 4. ขั้นตอนย้อนรอยหาเส้นทาง (Backtracking):
$$\hat{t}_{t-1} = bt_t(\hat{t}_t)$$

> 💡 **ทำไมต้องใช้ Log-space Viterbi:**  
> ในข้อความยาว ค่าความน่าจะเป็นจะเกิด **Arithmetic Underflow (ตัวเลขเข้าใกล้ 0 จนปัดเป็น 0.0)** การแปลงเป็น $\log$ จะเปลี่ยนการคูณเป็นผลรวม:  
> $$v_t(j) = \max_i \Big[ v_{t-1}(i) + \log a_{ij} \Big] + \log b_j(w_t)$$

### 5.2 รูปแบบการติดป้าย: เปรียบเทียบ IO vs BIO vs BIOES
- **IO Scheme:** มีแค่ `I-TYPE` และ `O` $\implies$ **ข้อจำกัด:** แยก 2 เอนทิตีชนิดเดียวกันที่อยู่ติดกันไม่ได้
- **BIO Scheme (IOB):** มี `B` (Begin), `I` (Inside), `O` (Outside) $\implies$ จำนวน Tag ทั้งหมด = $2K + 1$ (เมื่อ $K$ คือจำนวน Entity Type)
- **BIOES Scheme (BILOU):** มี `B` (Begin), `I` (Inside), `O` (Outside), `E` (End), `S` (Single — เอนทิตีที่มีความยาวเพียง 1 คำเดี่ยว)

| บริษัท | 0 | O | **O** | **O** | คำนำหน้าทั่วไป ไม่ใช่ชื่อเฉพาะ |

### 5.3 การประเมินผล NER (Strict Span-Level Evaluation — คำนวณด้วยเครื่องคิดเลข!)
> ⚠️ **กฎเหล็ก:** ห้ามวัดความแม่นยำด้วย Token-level Accuracy เพราะส่วนใหญ่เป็นป้าย `O` ทำให้ค่าสูงเกินจริง ต้องวัดที่ **Span-Level (ระดับขอบเขตของ Entity ที่สมบูรณ์)**

#### 1. สูตรการคำนวณ Precision, Recall, F1:
$$\text{Precision} (P) = \frac{\text{TP}}{\text{TP} + \text{FP}} = \frac{\text{จำนวน Entity ที่ทายถูกต้อง}}{\text{จำนวน Entity ที่ระบบทายออกมาทั้งหมด}}$$
$$\text{Recall} (R) = \frac{\text{TP}}{\text{TP} + \text{FN}} = \frac{\text{จำนวน Entity ที่ทายถูกต้อง}}{\text{จำนวน Entity ในเฉลยจริงทั้งหมด}}$$
$$F_1\text{-score} = \frac{2 \times P \times R}{P + R} = \frac{2 \times \text{TP}}{2 \times \text{TP} + \text{FP} + \text{FN}}$$

- **TP (True Positive):** ระบบทายถูกทั้ง **ขอบเขตคำ (Boundary)** และ **ประเภท Entity (Type)**
- **FP (False Positive):** ระบบทายขึ้นมา แต่ไม่มีในเฉลย หรือทายผิดประเภท หรือทายขอบเขตผิด
- **FN (False Negative):** Entity ในเฉลยที่ระบบตรวจจับไม่เจอ หรือทายขอบเขตตกหล่น

#### 2. ตัวอย่างการคำนวณจริงจาก Assignment 2 DIY 5:
- **Gold Entities (เฉลยจริง 5 ตัว):**
  1. `(สมชาย, PER)`
  2. `(เชียงใหม่, LOC)`
  3. `(ปตท., ORG)`
  4. `(กรุงเทพ, LOC)`
  5. `(2026, DATE)`
- **Predicted Entities (ระบบทาย 4 ตัว):**
  1. `(สมชาย, PER)`
  2. `(เชียง, LOC)`
  3. `(ปตท., ORG)`
  4. `(กรุงเทพ, ORG)`

**ขั้นตอนการตรวจนับ:**
1. หา **TP** (ตัวที่ตรงกัน 100%):
   - `(สมชาย, PER)` $\implies$ **TP**
   - `(ปตท., ORG)` $\implies$ **TP**
   - สรุป: **$\text{TP} = 2$**
2. หา **FP** (ตัวที่ระบบทาย แต่เฉลยไม่มี):
   - `(เชียง, LOC)` $\implies$ ขอบเขตคำผิด (เฉลยคือเชียงใหม่) นับเป็น **FP**
   - `(กรุงเทพ, ORG)` $\implies$ ประเภทผิด (เฉลยคือ LOC) นับเป็น **FP**
   - สรุป: **$\text{FP} = 2$**
3. หา **FN** (ตัวในเฉลย ที่ระบบทายไม่ถูก):
   - `(เชียงใหม่, LOC)` $\implies$ ระบบทายไม่ครบ นับเป็น **FN**
   - `(กรุงเทพ, LOC)` $\implies$ ระบบทายประเภทผิด นับเป็น **FN**
   - `(2026, DATE)` $\implies$ ระบบหาไม่เจอเลย นับเป็น **FN**
   - สรุป: **$\text{FN} = 3$**

**กดเครื่องคิดเลขคำนวณ:**
- $\text{Precision} = \frac{2}{2 + 2} = \frac{2}{4} = \mathbf{0.5000\text{ (50.00\%)}}$
- $\text{Recall} = \frac{2}{2 + 3} = \frac{2}{5} = \mathbf{0.4000\text{ (40.00\%)}}$
- $F_1\text{-score} = \frac{2 \times 0.5 \times 0.4}{0.5 + 0.4} = \frac{0.40}{0.90} \approx \mathbf{0.4444\text{ (44.44\%)}}$
- *การวิเคราะห์ผล:* ค่า Recall ต่ำกว่า Precision แสดงว่าระบบมีปัญหาเรื่องการตรวจจับ Entity ตกหล่น และปัญหาการตัดคำขอบเขตผิด (Boundary Segmentation Error)

### 6.1 เปรียบเทียบ Constituency Parsing vs Dependency Parsing (ตารางสรุป)
| คุณลักษณะ | Constituency Parsing | Dependency Parsing |
| :--- | :--- | :--- |
| **โครงสร้าง** | วลีซ้อนวลี (Nested Phrases: S, NP, VP, PP) | เส้นเชื่อมความสัมพันธ์ระหว่างคำต่อคำโดยตรง |
| **Root ของต้นไม้** | สัญลักษณ์ประโยค **Sentence ($S$)** | **กริยาหลัก (Main Verb / Root)** |
| **จำนวน Node** | จำนวนคำ + Non-terminal phrase nodes | **เท่ากับจำนวนคำในประโยคพอดี (1 node ต่อ 1 คำ)** |
| **สิ่งที่สื่อถึง** | การจัดกลุ่มคำในระดับวลี (Phrase-level grouping) | หน้าที่ทางไวยากรณ์ (Subject, Object, Modifier) |
| **ความสัมพันธ์หลัก** | NP, VP, PP, ADJP | `nsubj` (ประธาน), `dobj` (กรรมตรง), `det`, `amod`, `prep`, `pobj` |
| **เครื่องมือยอดนิยม** | Stanford PCFG Parser, NLTK | **spaCy**, Universal Dependencies, Stanza |

> 💡 **เทคนิคตรวจคำตอบเร็วในห้องสอบ:**  
> ถ้านับ Node ในต้นไม้แล้ว **จำนวน Node = จำนวนคำในประโยค** $\implies$ คือ **Dependency Tree**  
> ถ้ามี Node วลี $S, NP, VP$ เพิ่มขึ้นมา $\implies$ คือ **Constituency Tree**

### 6.2 ความกำกวมเชิงโครงสร้าง (Structural / PP-Attachment Ambiguity)
ประโยค: `"I saw the man with the telescope"` หรือ `"Students hate tests with errors"`
- **การตีความแบบที่ 1 (Attach กับ NP):**
  - วลี PP ขยายคำนามตัวหน้า: `[tests [with errors]]`
  - ความหมาย: นักศึกษาเกลียดข้อสอบที่มีข้อผิดพลาด
- **การตีความแบบที่ 2 (Attach กับ VP):**
  - วลี PP ขยายคำกริยา: `[hate tests] [with errors]`
  - ความหมาย: นักศึกษาทำการเกลียดข้อสอบอย่างผิดพลาด

```text
Constituency Tree 1 (PP attaches to NP):
        S
     ┌──┴──┐
    NP     VP
    │   ┌──┴──┐
    N   V     NP
    │   │   ┌─┴──┐
 students hate NP PP
               │  └──┐
               N  P  NP
               │  │  │
             tests with errors

Dependency Tree:
       hate (ROOT)
      ┌──┴────────┐
  students (nsubj) tests (dobj)
                  │
                 with (prep)
                  │
                errors (pobj)
```

### 6.3 Context-Free Grammar (CFG) และ Chomsky Normal Form (CNF)
- **CFG กฎการเขียนแทน:** $A \to \beta$ (ขยายสัญลักษณ์โดยไม่ขึ้นกับบริบทรอบข้าง)
- **Chomsky Normal Form (CNF):** บังคับให้กฎอยู่ใน 2 รูปแบบเท่านั้น:
  1. $A \to BC$ (แตกออกเป็น Non-terminal 2 ตัวเสมอ)
  2. $A \to w$ (แตกออกเป็นคำ Terminal 1 คำเสมอ)

---

### 6.4 The CYK Algorithm (Bottom-Up Dynamic Programming)
- ใช้ตรวจสอบว่าประโยคความยาว $n$ สร้างจาก CFG ในรูป CNF ได้หรือไม่
- **ขั้นตอนการเติมตารางสามเหลี่ยม $n \times n$:**
  1. **แถวล่างสุด (ความยาว Span = 1):** เติม Non-terminal ที่แตกออกมาเป็นคำ $w_i$ โดยตรง ($A \to w_i$)
  2. **แถวถัดไป (ความยาว Span $L = 2$ ถึง $n$):** สแกนหาจุดตัดแยก $k$ ระหว่างช่วง $(i, j)$:
     - ดูว่าถ้าช่วงซ้ายมีสัญลักษณ์ $B$ และช่วงขวามีสัญลักษณ์ $C$ และมีกฎ $A \to BC$ ให้ใส่ $A$ ลงในช่องตาราง $[i, j]$
  3. **ตรวจสอบคำตอบ:** ถ้าสัญลักษณ์เริ่มต้น **$S$** ปรากฏอยู่ในช่องบนสุดที่ครอบคลุมทั้งประโยค $[1, n] \implies$ ประโยคถูกต้องตามไวยากรณ์ (Valid)
- **Time Complexity:** $\mathcal{O}(n^3 \cdot |G|)$

---

### 6.5 Probabilistic CFG (PCFG) — คำนวณความน่าจะเป็นของ Tree (กดเครื่องคิดเลข!)
- แต่ละกฎจะมีค่าน้ำหนักความน่าจะเป็นกำกับ เช่น $P(S \to NP\ VP) = 1.0$ โดยผลรวมของกฎที่ออกจาก Non-terminal เดียวกันต้องเท่ากับ $1.0$
- **สูตรความน่าจะเป็นของ Parse Tree $T$:**
  $$P(T) = \prod_{\text{rule } r \in T} P(r)$$
- **ตัวอย่างการคำนวณ:**
  - สมมติ Tree 1 ใช้กฎ:
    - $S \to NP\ VP\ [1.0]$
    - $NP \to N\ [0.25]$ (students)
    - $VP \to V\ NP\ [0.5]$
    - $V \to \text{"hate"}\ [1.0]$
    - $NP \to NP\ PP\ [0.25]$
    - $NP \to N\ [0.25]$ (tests)
    - $PP \to P\ NP\ [1.0]$
    - $P \to \text{"with"}\ [1.0]$
    - $NP \to N\ [0.25]$ (errors)
  - คำนวณความน่าจะเป็นของ Tree 1:
    $$P(T_1) = 1.0 \times 0.25 \times 0.5 \times 1.0 \times 0.25 \times 0.25 \times 1.0 \times 1.0 \times 0.25 = \mathbf{0.001953}$$
  - นำค่า $P(T_1)$ ไปเทียบกับ $P(T_2)$ ต้นไม้ที่ได้ค่าความน่าจะเป็นสูงกว่าคือ **Most Probable Parse Tree**

### 7.1 Symbolic vs Distributional Representation
- **Symbolic (One-Hot Vector, Dictionary Index):**
  - มองแต่ละคำเป็นสัญลักษณ์เดี่ยวที่เป็นอิสระต่อกัน (Orthogonal)
  - ขนาดเวกเตอร์เท่ากับขนาดพจนานุกรม $|V|$ (ส่วนใหญ่เป็น 0 = Sparse)
  - **ข้อจำกัด:** ไม่มีความรู้เรื่องความคล้ายคลึงของคำ (`cat` ห่างจาก `kitten` เท่ากับ `car`)
- **Distributional Representation:**
  - *"You shall know a word by the company it keeps"* (J.R. Firth, 1957)
  - ความหมายของคำสามารถอนุมานได้จาก **บริบทของคำที่ปรากฏร่วมด้วยบ่อยๆ**

---

### 7.2 เปรียบเทียบ Sparse Vector vs Dense Vector
| มิติเปรียบเทียบ | Sparse Vector (TF-IDF, Co-occurrence) | Dense Vector (Word2Vec, GloVe) |
| :--- | :--- | :--- |
| **ขนาดมิติ (Dimension)** | มิติสูงมาก เท่ากับขนาด Vocabulary $|V|$ (~10,000–1,000,000) | มิติต่ำ คงที่ (~100–300 มิติ) |
| **ค่าในเวกเตอร์** | สมาชิกส่วนใหญ่เป็น **0** | สมาชิกแทบทุกมิติเป็น **ทศนิยมไม่เป็นศูนย์** |
| **ความหมายของมิติ** | แต่ละมิติแทนคำในคลังคำศัพท์โดยตรง | เข้ารหัสความหมายแฝงเชิงนามธรรม (Latent Semantic Features) |
| **ปัญหาหลัก** | สิ้นเปลืองหน่วยความจำ เกิดปัญหาคำพ้องความหมาย | ต้องใช้เวลาในการฝึกสอนโมเดล |

---

### 7.3 สูตรคำนวณ TF-IDF (กดเครื่องคิดเลข!)
1. **Term Frequency (TF):** ความถี่ของคำ $t$ ในเอกสาร $d$
   $$TF(t, d) = \text{Count}(t, d)$$
2. **Inverse Document Frequency (IDF):** วัดความเฉพาะเจาะจงของคำในคลังเอกสาร
   $$IDF(t) = \log_{10}\left(\frac{N}{DF(t)}\right)$$
   *(เมื่อ $N$ คือจำนวนเอกสารทั้งหมด, $DF(t)$ คือจำนวนเอกสารที่มีคำ $t$ ปรากฏ)*
3. **TF-IDF:**
   $$TF\text{-}IDF(t, d) = TF(t, d) \times IDF(t)$$

> 💡 **เกร็ดคำนวณ:**  
> ถ้าคำ $t$ ปรากฏใน **ทุกเอกสาร** ($DF = N$) $\implies IDF = \log_{10}(1) = \mathbf{0} \implies TF\text{-}IDF = \mathbf{0}$ (ลดน้ำหนักคำหยุดเช่น `"the"`, `"is"` โดยอัตโนมัติ)

---

### 7.4 สูตรคำนวณ Cosine Similarity (กดเครื่องคิดเลข!)
$$\text{Cosine}(u, v) = \frac{u \cdot v}{\|u\| \|v\|} = \frac{\sum_{i=1}^d u_i v_i}{\sqrt{\sum_{i=1}^d u_i^2} \times \sqrt{\sum_{i=1}^d v_i^2}}$$

**ตัวอย่างคำนวณ:**
สมมติเวกเตอร์คำ: $u = [1, 2, 3]$ และ $v = [2, 0, 1]$
1. Dot Product: $u \cdot v = (1)(2) + (2)(0) + (3)(1) = 2 + 0 + 3 = \mathbf{5}$
2. ขนาด $\|u\| = \sqrt{1^2 + 2^2 + 3^2} = \sqrt{1 + 4 + 9} = \sqrt{14} \approx 3.7417$
3. ขนาด $\|v\| = \sqrt{2^2 + 0^2 + 1^2} = \sqrt{4 + 0 + 1} = \sqrt{5} \approx 2.2361$
4. $\text{Cosine}(u, v) = \frac{5}{3.7417 \times 2.2361} = \frac{5}{8.3666} \approx \mathbf{0.5976}$

### 7.5 Word2Vec: Skip-gram vs CBOW
```text
           CBOW                                Skip-gram
 Context Words ──┐                  Target Word ──────┬──> Context Word 1
 Context Words ──┼──> Target Word                     ├──> Context Word 2
 Context Words ──┘                                    └──> Context Word 3
(หลายคำ ทาย 1 คำกลาง)                         (1 คำกลาง ทาย หลายคำรอบข้าง)
```
- **CBOW (Continuous Bag-of-Words):**
  - นำคำบริบทรอบข้างมารวมกันเพื่อทำนายคำตรงกลาง
  - **จุดเด่น:** เทรนเร็วกว่า เหมาะกับคำที่พบบ่อย (Frequent words)
- **Skip-gram:**
  - นำคำเป้าหมายตรงกลางมาทำนายคำบริบทรอบข้าง
  - **จุดเด่น:** ทำงานได้ดีกับ Dataset ขนาดเล็ก และเก็บความหมายของ **คำหายาก (Rare words)** ได้ดีกว่า
- **Negative Sampling (SGNS):** เทคนิคสุ่มคำลบ $k$ คำ (เช่น 5 คำ) มาฝึกร่วมกับคำจริง เพื่อหลีกเลี่ยงการคำนวณ Softmax เต็มทั้ง Vocabulary ซึ่งกินเวลามาก
- **Semantic Vector Arithmetic (ความสัมพันธ์เชิงความหมาย):**
  $$\vec{v}(\text{king}) - \vec{v}(\text{man}) + \vec{v}(\text{woman}) \approx \vec{v}(\text{queen})$$
  $$\vec{v}(\text{Paris}) - \vec{v}(\text{France}) + \vec{v}(\text{Italy}) \approx \vec{v}(\text{Rome})$$

---

### 7.6 GloVe และ Contrastive Learning ยุคใหม่
- **GloVe (Global Vectors):** เรียนรู้จากเมทริกซ์สถิติการปรากฏร่วมระดับโกลบอล (Global Co-occurrence Matrix) ทั้งคลังข้อความ ไม่ได้ดูแค่หน้าต่างบริบทเฉพาะจุดแบบ Word2Vec
- **Contrastive Learning (หลักการดึงเข้า-ผลักออก):**
  - ดึงคู่ที่เหมือนกัน (Positive pairs) ให้เข้าใกล้กัน
  - ผลักคู่ที่ต่างกัน (Negative pairs) ให้ออกห่างกัน
- **โมเดลสำคัญในกลุ่ม Representation:**
  - **MUSE:** จัดระเบียบ Word Embeddings หลายภาษาให้อยู่ใน Shared Multilingual Vector Space เดียวกัน
  - **SimCSE:** Sentence Embedding โดยใช้เทคนิค Dropout Noise สร้าง Positive pair
  - **BGE:** โมเดล Embedding สำหรับงานสืบค้นข้อความ (Dense Retrieval / Search)
  - **CLIP:** เชื่อมโยง Image และ Text ใน Joint Multimodal Embedding Space เดียวกัน

### 🚨 สรุปสูตรคำนวณทั้งหมดที่ต้องใช้เครื่องคิดเลข

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. HMM Viterbi Recursion Cell                                               │
│    v_t(j) = max_i [ v_{t-1}(i) * a_{ij} ] * b_j(w_t)                       │
│    Log-space: v_t(j) = max_i [ v_{t-1}(i) + log(a_{ij}) ] + log(b_j(w_t))   │
├─────────────────────────────────────────────────────────────────────────────┤
│ 2. NER Span-Level Metrics                                                   │
│    Precision = TP / (TP + FP)                                               │
│    Recall    = TP / (TP + FN)                                               │
│    F1-score  = 2 * P * R / (P + R)  =  2*TP / (2*TP + FP + FN)              │
├─────────────────────────────────────────────────────────────────────────────┤
│ 3. Bigram Probability                                                       │
│    P(w_i | w_{i-1}) = Count(w_{i-1}, w_i) / Count(w_{i-1})                  │
│    P(Sequence)      = P(w_1) * P(w_2|w_1) * ... * P(w_k|w_{k-1})            │
├─────────────────────────────────────────────────────────────────────────────┤
│ 4. Probabilistic CFG (PCFG) Parse Tree                                      │
│    P(Tree) = ∏_{r ∈ Tree} P(rule_r)                                         │
├─────────────────────────────────────────────────────────────────────────────┤
│ 5. TF-IDF                                                                   │
│    IDF(t) = log10( N / DF(t) )                                              │
│    TF-IDF = TF(t, d) * IDF(t)                                               │
├─────────────────────────────────────────────────────────────────────────────┤
│ 6. Cosine Similarity                                                        │
│    cos(u, v) = (u · v) / ( ||u|| * ||v|| )                                  │
│              = (∑ u_i*v_i) / ( √(∑ u_i^2) * √(∑ v_i^2) )                   │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 🎯 5 กับดักข้อสอบที่ต้องระวัง (Exam Pitfalls)
1. **NER ไม่คิดคะแนนที่ป้าย `O`:** ในการคิด Precision/Recall/F1 ให้นับเฉพาะกลุ่มคำที่เป็น Entity จริงเท่านั้น ป้าย `O` ไม่นำมาคิดใน TP/FP/FN
2. **Strict Span Matching:** ถ้าเฉลยคือ `"เชียงใหม่/LOC"` แต่ระบบทาย `"เชียง/LOC"` $\implies$ ผิดทั้งคู่! ได้ **1 FP** (จากการทายผิดขอบเขต) และได้ **1 FN** (เพราะทายตัวจริงไม่สำเร็จ)
3. **FMM vs BMM:** FMM ตัดคำยาวสุดจากหน้าไปหลัง; BMM ตัดคำยาวสุดจากหลังมาหน้า ถ้าเจอกรณีความกำกวม เช่น `"อากาศตากลม"` ผลลัพธ์มักไม่เท่ากัน
4. **Dependency Tree Node Count:** จำนวน Node ของ Dependency Tree ต้องเท่ากับจำนวนคำในประโยคพอดี ถ้ามี Node เกินแสดงว่าเผลอไปวาด Constituency Tree
5. **IDF เป็น 0:** ถ้าคำปรากฏในทุกเอกสาร ($DF = N$) ค่า $IDF = \log(N/N) = \log(1) = 0$ อย่าตกใจ เป็นเรื่องปกติของคำที่ไร้ประโยชน์เชิงการจำแนก
